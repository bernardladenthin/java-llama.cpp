# Bug-Hunt: geprüfte Stellen — java-llama.cpp

Jede Zeile unter „Geprüft“ steht für eine gründlich gelesene Produktionsdatei, **genau eine Zeile je Pfad**:
`Pfad` · Blob-Hash der Datei beim Prüfen · Datum der letzten Lesung · Ergebnis — Notizen. Eine Datei gilt als
geprüft, solange `git rev-parse --short HEAD:<Pfad>` denselben Blob-Hash liefert. Ändert sich die Datei, wandert
ihre Zeile nach „Abgelaufen – erneut zu prüfen“, mit dem Blob am HEAD und den Fixes, die sie seitdem geändert
haben; zurück unter „Geprüft“ kommt sie erst mit einer neuen vollständigen Lesung und dem dann gelesenen Blob.
Eine Zeile wird nie umdatiert oder auf einen neuen Blob gesetzt, ohne die Datei erneut gelesen zu haben (ein
geprüfter Fix-Diff ist keine Lesung der Klasse). Ergebnisse: `kein Fund`, `widerlegt` (Verdacht geprüft, Code
korrekt), `unsicher` (offen, siehe [`BUGHUNT-FOUND.md`](BUGHUNT-FOUND.md)), `Fund Fnn` (Fehler gefunden und dort
beschrieben). Mehrere Durchsichten derselben Datei am selben Blob stehen in einer Zeile, getrennt durch `‖`.

Bis 2026-10-20 wurde je Durchsicht eine Zeile angehängt (274 Zeilen für 124 Pfade, von denen am 2026-10-21
43 abgelaufen waren); am 2026-10-21 wurde die Datei auf eine Zeile je Pfad zusammengeführt, ohne eine Datei neu
zu lesen. Prüfung, ob eine Zeile unter „Geprüft“ abgelaufen ist (gibt nichts aus, solange alle stimmen):

```bash
sed -n '/^## Geprüft/,/^## Abgelaufen/p' BUGHUNT-CHECKED.md | sed -n 's/^- `\([^`]*\)` · `\([0-9a-f]*\)`.*/\1 \2/p' |
  while read -r p h; do c=$(git rev-parse HEAD:"$p"); case "$c" in "$h"*) ;; *) echo "abgelaufen: $p ($h, HEAD ${c:0:7})";; esac; done
```
