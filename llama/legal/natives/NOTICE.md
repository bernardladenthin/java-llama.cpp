# Third-party code in the java-llama.cpp natives

Every natives jar of `net.ladenthin:llama` (and the two Android AARs) carries this directory under
`META-INF/third-party/natives/` (the AARs under `META-INF/third-party/<artifactId>/natives/` inside
their `classes.jar`). It holds the license texts of everything compiled into the native libraries:
java-llama.cpp's own code (`java-llama.cpp/`), llama.cpp/ggml at the pinned commit (`llama.cpp/`) and
the code llama.cpp vendors or derives from other projects, BoringSSL, the GPU vendors' header
libraries compiled into a backend module, and the npm packages of the embedded WebUI
(`webui-npm/`, generated by `.github/webui-licenses.py`). Each folder's `SOURCE.txt` names where
its text was taken from, byte for byte. A jar carries the texts of every kind of natives
directory; the table says which component is in which.

Runtimes that are only loaded at run time and not shipped (the CUDA, ROCm, oneAPI, Level Zero,
OpenCL ICD and OpenVINO runtimes, the system C/C++ libraries) are listed for completeness; their
texts are not needed here.
